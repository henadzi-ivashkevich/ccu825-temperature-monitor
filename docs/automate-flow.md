# Automate flow: RADSEL CCU825 → Google Sheets

Этот документ отражает схему, переданную владельцем проекта. Названия переменных и состав запросов сохранены; секретные значения намеренно не включены.

## Последовательность блоков

```text
RADSEL CCU825
    ↓
HTTP GET (Automate) → ccuResponse
    ↓
HTTP POST (Automate) → googleResponse, googleStatus
    ↓
Google Apps Script → Google Sheets (лист «мониторинг»)
    ↓
Задержка 30 минут
    └──────────────→ обратно к HTTP GET
```

1. Блок **HTTP request** выполняет первый `GET` к контроллеру RADSEL CCU825. JSON-ответ сохраняется в переменную `ccuResponse`.
2. Следующий блок **HTTP request** выполняет `POST` на URL веб-приложения Apps Script `/exec` с типом содержимого `application/json`.
3. Тело POST формируется выражением Automate `jsonEncode()`:

   ```text
   jsonEncode({
     "token": "<API_TOKEN из Script Properties>",
     "payload": jsonDecode(ccuResponse)
   })
   ```

   В реальном потоке строковый placeholder заменяется текущим значением токена. `jsonDecode(ccuResponse)` передаёт разобранный объект CCU в `payload`, а `jsonEncode()` сериализует всё тело запроса.
4. Текст ответа POST сохраняется в `googleResponse`, HTTP-статус — в `googleStatus`.
5. Блок задержки ждёт 30 минут и возвращает поток к первому HTTP GET.

## Секреты и доступ

- Apps Script хранит проверочный токен в **Script Properties** под именем `API_TOKEN`. В `Code.gs` хранится только имя свойства; в исходнике нет значения секрета.
- ID Google-таблицы читается из Script Property `SPREADSHEET_ID`; в исходнике он также не зашит. Сам ID — идентификатор ресурса, а не пароль, и не заменяет права доступа Google.
- Automate отправляет тот же токен в JSON-поле `token` по HTTPS вместе с `payload`. В предоставленной схеме не указано, есть ли в используемой версии Automate защищённое хранилище секретов. Поэтому считайте токен в поле/переменной потока чувствительным: не добавляйте незамаскированный экспорт потока в Git.
- Первый GET к контроллеру и его возможная авторизация в предоставленной схеме не раскрыты; этот документ не предполагает, что у контроллера есть отдельный API key.
- `API_TOKEN` защищает POST-запись. Текущий GET истории Apps Script не проверяет этот токен; если веб-приложение доступно всем, историю можно читать по URL. Проверьте настройку доступа к веб-приложению перед публикацией URL.
- Токен из присланного текущего скрипта следует считать раскрытым и заменить новым. Установите новый токен в Script Properties и в POST-поле Automate; не помещайте его в репозиторий.
